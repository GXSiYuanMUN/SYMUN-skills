# 坑与症状对照

> 全部来自真实执行，不是推测。按"症状 → 原因 → 处置"排，遇到问题可以直接搜症状。

## 一、执行阶段

| 症状 | 原因 | 处置 |
|---|---|---|
| 改名失败 / 提示目录被占用 | 有进程占着数据目录。**Git Bash 最常见** —— PortableGit 就住在 `.workbuddy\vendor` 里 | 关掉所有终端、VS Code、资源管理器窗口再跑 |
| "您没有足够的权限" | 用了符号链接 `mklink /D` | 改用目录联接 `mklink /J`（无需管理员） |
| `robocopy` 报 3 个文件失败 | 运行中的 live 文件（sqlite db / `-wal` / 日志）被占用 | **正常**。第二遍增量同步会补齐 |
| `robocopy /L` 报 `*多余文件` | 第一遍复制后程序删掉了某些缓存，目标盘还留着 | 无害，不用管 |
| `robocopy` 退出码 8 以上 | 真失败：权限不足、目标盘掉线、路径不存在 | 看日志定位，别硬着头皮往下走 |
| 搬完程序像被重置 | **忘了在原路径建联接** | 跑 `9_rollback.bat` 重来，这次别漏第 4 步 |
| 联接建好但程序打不开 | 目标盘是 U 盘 / 移动硬盘 / 网络盘 | 必须搬回固定盘 |
| `.bat` 双击闪退 / 中文乱码 | 写成了 UTF-8 + LF | 必须 **ANSI 码页 + CRLF**；本技能由 `make_bat.py` 自动处理 |
| 联接建了，但路径里带中文导致失败 | 批处理按系统 ANSI 解析，UTF-8 中文路径会变乱码 | 用 `make_bat.py` 生成（自动按 ANSI 写），或先把目录改成 ASCII |

## 二、验收阶段

| 症状 | 原因 | 处置 |
|---|---|---|
| 资源管理器里 C 盘那个目录体积显示很小 | 联接的特性：显示的是链接本身，不是内容 | 正常。用 `diagnose.py` 看真实路径与体积 |
| 用 `os.path.islink()` 判断，显示 `False`，以为联接丢了 | **`islink()` 对目录联接返回 `False`** | 改用 `os.readlink()`：能读出来就是联接 |
| 搬完 C 盘没变大 | ①旧副本还没删（`3_cleanup.bat` 没跑）②别的东西又占满了 | 先确认 `_old` 是否还在，再重新盘点 |
| 技能少了几个 | 复制时被占用、或原目录里本来就有坏链接 | 对比 `diagnose.py` 的基线数字，逐个核对 |
| 自动化条数对不上 | 统计时没过滤 `deleted_at`（软删除仍在表里） | 用 `list_automations.py`，它已过滤 |

## 三、长期运行阶段

| 症状 | 原因 | 处置 |
|---|---|---|
| 搬完一两个月，C 盘又满了 | 搬迁只解决"被搬的那部分"。系统更新、新软件、程序新增目录都会重新占 | 重跑 `diagnose.py`，做全网盘盘点，别只盯 WorkBuddy |
| 升级版本后怀疑"联接白做了" | 升级最容易触发这种怀疑，但实际联接最稳 | 升级照常读写原路径 → 自动穿透。跑一次体检清单即可放心 |
| 升级后界面里"任务全没了" | 任务绑在别的工作区，或 `owner_status` 仍是遗留状态 | `list_automations.py` 核对；打开对应工作区就能看到 |
| 两条任务重复执行 | 同 cwd、同计划的两条定义（旧 `automation-<时间戳>` 与 `uuid` 并存） | 只保留一条，另一条软删除 |
| 自动化到点不跑 | 绑定的工作目录被删了 / 改名了 | 脚本会标 `<工作目录已不存在！>`；恢复目录或改绑定 |
| `workbuddy.db-wal` 很大 | WAL 未 checkpoint，属正常 | 不是损坏，别手工删 |

## 四、最容易犯的四个思维错误

| 错误想法 | 现实 |
|---|---|
| "搬走就完事了，C 盘从此宽裕" | 搬迁是止血。实测搬走 6.2 GB 后，一个月内被系统更新吃回去大半 |
| "界面看不到 = 数据丢了" | 界面按工作区过滤，数据库才是全量。判断有无一律以 db 为准 |
| "换路径打开就行，不用建联接" | 历史会话索引和 `workspaces` 表还记着老路径，换了就断 |
| "删了重建更干净" | 浏览器 profile 删了会丢登录态，下次用自动化技能前要重新扫码。**搬而不删** |

## 五、红线

1. **切换前必须完全退出程序**。程序在跑时改它自己的目录，会产生"老进程句柄指旧路径、新进程指新路径"的混合状态，这种状态极难排查。
2. **不要当天删旧副本**。观察 3–7 天。删了之后唯一的退路是"重搬一遍"。
3. **旧副本不要进回收站**。回收站不释放空间，与目的直接冲突 —— 所以用 `rd /s /q`，但必须二次确认 + 前置校验联接在位。
4. **不要为了省事跳过校验**。`robocopy /L` 那一步只花几十秒，能挡住"搬了一半"这种最难恢复的情况。
